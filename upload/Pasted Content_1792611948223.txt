# PROMPT MAÎTRE — CRÉATION D'UNE PLATEFORME E-COMMERCE COMPLÈTE AVEC ADMINISTRATION VISUELLE ET MARKETING AVANCÉ

## 1. TON RÔLE

Tu es un ingénieur logiciel senior, architecte SaaS, développeur full-stack, expert en e-commerce, UX/UI, sécurité, marketing automation, gestion des paiements et bases de données.

Ta mission est de construire une véritable plateforme e-commerce professionnelle, complète, sécurisée, responsive et exploitable en production.

Je ne suis pas développeur. Tu dois donc prendre en charge les décisions techniques, expliquer simplement les actions importantes et me permettre de gérer ma boutique sans modifier le code.

**Je ne veux pas uniquement une maquette ou un dashboard avec des boutons non fonctionnels. Je veux une application réelle, connectée à sa base de données, dans laquelle les fonctionnalités annoncées sont effectivement opérationnelles.**

Si tu travailles dans un projet existant, commence par analyser son architecture, ses fichiers, ses tables et ses fonctionnalités avant de modifier quoi que ce soit. Conserve le travail déjà réalisé et évite toute réécriture inutile.

Si le projet est nouveau, initialise une architecture propre et évolutive.

Ne supprime jamais une fonctionnalité existante sans m'en avertir. Ne modifie pas les règles financières ou de paiement sans analyser leurs conséquences.

# 2. OBJECTIF GÉNÉRAL

Construire une plateforme e-commerce inspirée de l'expérience utilisateur des meilleures boutiques Shopify, avec deux interfaces principales.

### Interface A — Boutique publique

C'est la boutique visible par les visiteurs et les clients.

Elle doit permettre de :

- découvrir les produits ;
- consulter les catégories ;
- rechercher et filtrer les produits ;
- consulter les fiches produits ;
- choisir les variantes ;
- ajouter des produits au panier ;
- utiliser des coupons ;
- passer commande ;
- choisir un moyen de paiement disponible ;
- consulter les informations de commande ;
- accéder aux produits numériques achetés ;
- créer un compte client ;
- parrainer d'autres clients ;
- consulter ses récompenses ;
- publier des avis lorsque cela est autorisé.

### Interface B — Administration

C'est l'espace privé permettant de gérer toute la boutique.

L'administrateur doit pouvoir gérer les produits, les commandes, les clients, les paiements, les promotions, les parrainages, les récompenses, le design, les pages, les utilisateurs et les statistiques.

L'objectif est de proposer une expérience d'administration comparable aux grandes plateformes e-commerce, avec un système de personnalisation visuelle proche du fonctionnement d'Elementor.

**L'administrateur ne doit pas avoir besoin de coder pour modifier le contenu, l'apparence ou les offres commerciales de la boutique.**

# 3. ACCÈS À L'ADMINISTRATION

Je veux accéder à l'administration en saisissant directement :

`/admin`

Exemple :

`https://mondomaine.com/admin`

Le fonctionnement doit être similaire à celui de WordPress :

- si l'utilisateur n'est pas connecté, il est redirigé vers une page de connexion ;
- après une connexion autorisée, il accède au dashboard ;
- après déconnexion, les pages privées deviennent inaccessibles ;
- un client ordinaire ne doit pas pouvoir accéder à l'administration ;
- un utilisateur sans permission ne doit pas pouvoir exécuter une action interdite.

Prévois également une route de connexion dédiée, par exemple `/admin/login`, sans imposer à l'utilisateur de connaître cette route pour accéder à l'administration.

**Important :** la sécurité ne doit jamais dépendre du fait que l'URL `/admin` soit connue ou non. Chaque page, action serveur et API doit vérifier l'identité et les permissions de l'utilisateur.

## Rôles

Prévois au minimum :

- OWNER : propriétaire de la boutique ;
- ADMIN : administrateur ;
- MANAGER : responsable d'équipe ou d'activité ;
- MARKETING : gestionnaire des promotions et campagnes ;
- STAFF : personnel avec accès limité ;
- CUSTOMER : client ;
- VISITOR : visiteur non connecté.

L'OWNER doit pouvoir gérer les rôles et permissions.

Les permissions doivent être configurables, par exemple :

- consulter les commandes ;
- modifier les commandes ;
- gérer les produits ;
- gérer le stock ;
- gérer les clients ;
- gérer les promotions ;
- créer des récompenses ;
- approuver un remboursement ;
- gérer les paiements ;
- modifier le thème ;
- publier des pages ;
- consulter les statistiques ;
- gérer les utilisateurs.

Une permission doit être vérifiée côté serveur, et pas uniquement en masquant un bouton dans l'interface.

Je veux éviter l'apparence générique des sites générés automatiquement par une IA.

La boutique doit avoir une identité visuelle professionnelle, cohérente et travaillée.

Inspire-toi des standards de qualité des thèmes Shopify haut de gamme :

- typographie moderne ;
- espaces blancs bien maîtrisés ;
- hiérarchie visuelle claire ;
- grilles de produits soignées ;
- cartes élégantes ;
- boutons travaillés ;
- menus professionnels ;
- transitions fluides ;
- animations discrètes ;
- effets au survol ;
- galeries produits agréables ;
- menus mobiles ergonomiques ;
- pages produits visuellement convaincantes ;
- panier et checkout cohérents avec le reste de la boutique.

Utilise une police adaptée, par exemple Inter, Geist ou Manrope, avec une solution de repli fiable.

Prévois :

- animations d'apparition discrètes ;
- transitions de navigation lorsque cela est pertinent ;
- animations des boutons ;
- interactions fluides des menus ;
- transitions des images produits ;
- tiroir de panier animé ;

- indicateurs de chargement élégants ;
- animations respectant la préférence système de réduction des mouvements.

Le résultat doit être professionnel sur smartphone, tablette et ordinateur.

Ne copie pas exactement le code source, les ressources propriétaires ou un thème Shopify commercial protégé. Crée une identité originale en reprenant les bonnes pratiques d'ergonomie et les interactions qui rendent ces boutiques professionnelles.

Le design doit rester cohérent sur toutes les pages, y compris l'administration.

L'administration doit proposer un véritable module de gestion des produits.

L'administrateur doit pouvoir :

- modifier un produit ;
- dupliquer un produit ;

- modifier le prix ;

- gérer les images et vidéos ;
- définir un SKU ;
- gérer les variantes ;
- gérer le stock ;
- associer des catégories ;
- ajouter des tags ;
- gérer les attributs ;
- gérer les produits recommandés ;
- importer et exporter des produits lorsque cela est possible.

## Trois types de produits obligatoires

### A. Produit physique

Exemples : vêtements, accessoires, appareils électroniques.

Fonctionnalités :

- stock ;
- SKU ;
- variantes ;
- livraison ;
- suivi de commande ;
- disponibilité ;
- gestion des ruptures de stock.

### B. Produit numérique

Exemples : PDF, ebook, formation, fichier téléchargeable ou ressource numérique.

Fonctionnalités :

- téléversement sécurisé ;
- stockage privé ;
- gestion des fichiers ;
- droit d'accès associé à une commande ;
- téléchargement après confirmation du paiement ;
- limites de téléchargement configurables ;
- journal des téléchargements ;
- révocation des droits lorsque la commande doit être invalidée.

Les fichiers payants ne doivent pas être accessibles par une URL publique permanente.

### C. Produit hybride

Un produit hybride contient une partie physique et une partie numérique.

Exemple : un appareil vendu avec un guide PDF.

Il doit pouvoir gérer simultanément :

- le stock physique ;
- les frais et règles de livraison ;
- le fichier numérique ;
- les droits de téléchargement ;
- les statuts de commande et de paiement.

Une commande hybride payée à la livraison ne doit pas débloquer automatiquement le fichier numérique avant confirmation du paiement.

# 8. PANIER ET PROCESSUS DE COMMANDE

Crée un véritable système de panier et de checkout.

Le panier doit permettre :

- ajouter un produit ;
- supprimer un produit ;
- modifier les quantités ;
- choisir une variante ;
- appliquer un coupon ;
- consulter les réductions ;
- calculer la livraison ;
- consulter le total ;
- gérer les produits indisponibles ;
- gérer les quantités supérieures au stock ;
- recalculer le prix côté serveur ;
- afficher clairement les erreurs.

Le checkout doit gérer :

- commande avec compte client ;
- commande invitée si autorisée ;
- informations client ;
- téléphone ;
- adresse ;
- ville ;
- zone de livraison ;
- méthode de livraison ;
- méthode de paiement ;
- validation de la commande ;
- confirmation de commande ;
- suivi de commande.

Les totaux ne doivent jamais être considérés comme fiables simplement parce qu'ils ont été envoyés par le navigateur. Le serveur doit recalculer le montant à partir des données réelles.

## Séparation obligatoire des statuts

Utilise des statuts distincts pour les commandes et les paiements.

Exemples de statuts de commande :

- PENDING ;
- CONFIRMED ;
- PROCESSING ;
- SHIPPED ;
- DELIVERED ;
- CANCELLED ;
- REFUNDED.

Exemples de statuts de paiement :

- PAYMENT_PENDING ;
- PAYMENT_PAID ;
- PAYMENT_FAILED ;
- PAYMENT_CANCELLED ;
- PAYMENT_REFUNDED ;
- PAYMENT_PARTIALLY_REFUNDED.

Créer une commande ne signifie jamais que son paiement a été effectué.

Un paiement n'est confirmé qu'après une vérification fiable : webhook vérifié, confirmation serveur du fournisseur ou action manuelle autorisée et journalisée.

Si les identifiants d'un fournisseur ne sont pas disponibles, indique clairement que son intégration nécessite une configuration. Ne simule pas un paiement réel et ne présente jamais un test local comme une intégration de production.

Les webhooks doivent être vérifiés, sécurisés et idempotents.

Pour la livraison, prévois :

- livraison gratuite ;

# 11. OUTIL MARKETING N° 1 — ACHETEZ X, OBTENEZ Y

Créer un moteur de promotions quantitatives configurable depuis l'administration.

L'administrateur doit pouvoir créer des règles comme :

- achetez 2 produits, obtenez 1 produit gratuit ;
- achetez 3 produits, obtenez une réduction sur le quatrième ;
- achetez 5 produits, payez-en 4 ;
- achetez X unités, obtenez Y unités ;
- achetez un produit spécifique et obtenez un autre produit ;
- achetez un montant défini et recevez une récompense.

## Configuration

L'administrateur doit pouvoir définir :

- nom ;
- description ;
- produits concernés ;
- catégories concernées ;
- quantité requise ;
- quantité offerte ;
- produit offert ;
- pourcentage de réduction ;
- montant fixe de réduction ;
- date de début ;
- date de fin ;

- nombre maximum d'utilisations ;
- limite par client ;
- stock disponible pour les produits offerts ;

La promotion doit être calculée côté serveur.

Elle doit apparaître correctement dans le panier, le checkout, la commande et les rapports.

Le système doit éviter les doublons, les dépassements de limites et les réductions sur des produits non éligibles.

Une promotion expirée ou désactivée ne doit plus s'appliquer.

# 12. OUTIL MARKETING N° 2 — PARRAINAGE AVEC COMMISSION FIXE OU EN POURCENTAGE

Chaque client éligible doit pouvoir disposer d'un code de parrainage unique et d'un lien partageable.

Le client peut partager son code avec des amis ou connaissances.

Lorsqu'un nouveau client utilise ce code, le système doit enregistrer l'attribution du parrainage.

## Fonctionnalités client

Prévois une page de parrainage dans le compte client permettant de consulter :

- son code ;
- son lien ;
- le nombre de filleuls ;
- les commandes éligibles ;
- les récompenses en attente ;
- les récompenses disponibles ;
- les récompenses utilisées ;
- l'historique ;
- les conditions du programme.

## Configuration administrateur

L'administrateur doit pouvoir choisir :

- activation ou désactivation du programme ;
- montant fixe de commission ;
- pourcentage de commission ;
- base de calcul de la commission ;
- plafond de commission ;
- commande minimum ;
- produits ou catégories éligibles ;
- période de validité ;
- délai avant validation ;
- nombre maximum de récompenses ;
- nombre maximum de filleuls ;
- conditions d'éligibilité ;
- mode de récompense.

Les récompenses peuvent prendre la forme de :

- crédit boutique ;
- coupon ;
- commission en attente ;
- remboursement manuel lorsque cela est autorisé.

## Règles obligatoires

Empêcher :

- l'auto-parrainage ;
- l'utilisation de son propre code ;
- les attributions multiples incompatibles ;
- les récompenses en double ;
- les commandes fictives ;
- les récompenses issues de commandes non payées ;
- la fraude par annulation ou remboursement.

Une récompense ne devient éligible qu'après le respect des conditions du programme et la confirmation du paiement de la commande concernée.

Si une commande source est annulée, remboursée ou reconnue comme frauduleuse, la récompense doit pouvoir être suspendue ou annulée conformément aux règles configurées.

# 13. OUTIL MARKETING N° 3 — PARRAINAGE AVEC REMBOURSEMENT INTÉGRAL CONDITIONNEL

Créer un deuxième programme de parrainage distinct du programme à commission.

L'objectif est de permettre à un client de recevoir le remboursement intégral de sa propre commande éligible s'il recommande un nombre défini de clients qui réalisent effectivement des achats admissibles.

Exemple :

Un client achète un produit pour 30 000 FCFA.

L'administrateur configure la règle suivante :

« Si vous recommandez 5 nouveaux clients dont les commandes admissibles sont payées, vous pouvez obtenir le remboursement de votre commande éligible, selon les conditions du programme. »

Cet exemple sert à illustrer le fonctionnement. Tous les montants et le nombre de filleuls doivent être configurables.

## Configuration administrateur

L'administrateur doit pouvoir définir :

- nombre de filleuls requis ;
- définition d'un filleul valide ;
- montant minimum de chaque commande ;
- nombre minimum de commandes payées ;
- produits éligibles ;
- catégories éligibles ;
- commande du parrain éligible ;
- pourcentage de remboursement ;
- plafond de remboursement ;
- montant minimum ;
- date de début ;
- date de fin ;
- limite de récompenses ;
- délai de validation ;
- conditions supplémentaires ;
- activation et désactivation du programme.

Le pourcentage peut atteindre 100 % du montant éligible lorsque les conditions le permettent.

## Modes de remboursement

Prévois plusieurs modes configurables :

- crédit boutique ;
- coupon d'une valeur équivalente ;
- remboursement manuel ;
- remboursement automatique uniquement si le fournisseur de paiement permet réellement cette opération et si toutes les conditions de sécurité sont remplies.

L'administrateur doit pouvoir distinguer clairement un crédit boutique d'un remboursement réel envoyé au client.

## Déclenchement de la récompense

La récompense doit être déclenchée uniquement après :

1. l'attribution correcte des filleuls ;
2. la vérification de leur unicité ;
3. la validation de leurs commandes éligibles ;
4. la confirmation réelle de leurs paiements ;
5. la vérification du nombre requis de commandes ;
6. la vérification de la commande du parrain ;
7. la vérification des plafonds et des règles anti-fraude.

Une commande simplement créée ne compte pas comme une commande payée.

Une commande en attente, échouée ou annulée ne doit pas compter comme une commande qualifiante.

Une commande remboursée doit être traitée selon les règles de réversibilité définies par le programme.

## Protection contre les doublons

Une même commande du parrain ne doit pas générer plusieurs remboursements pour la même campagne.

Chaque récompense doit posséder un identifiant unique, une commande source, une règle de programme et un historique complet.

Les récompenses doivent avoir des statuts explicites, par exemple :

- REWARD_PENDING ;
- REWARD_APPROVED ;
- REWARD_AVAILABLE ;
- REWARD_USED ;
- REWARD_PAID ;
- REWARD_CANCELLED.

L'administrateur doit pouvoir vérifier manuellement les récompenses importantes avant leur validation définitive.

Le stock, la livraison, les réductions, les paiements et les historiques doivent rester cohérents.

L'acceptation d'un upsell doit être enregistrée et reliée à la commande initiale.

# 16. TOUTES LES FONCTIONNALITÉS MARKETING DOIVENT ÊTRE CONNECTÉES AUX COMMANDES

C'est une exigence centrale.

Les promotions, coupons, parrainages, remboursements conditionnels et upsells doivent partager une logique métier cohérente.

- commande annulée ;

- parrainage attribué ;
- commande de filleul validée ;
- récompense calculée ;
- récompense approuvée ;
- récompense annulée ;
- upsell accepté.

Chaque événement doit être associé aux identifiants pertinents de la commande, du client, du programme et de la récompense.

Les traitements doivent être idempotents : un même événement reçu plusieurs fois ne doit pas créer plusieurs paiements, commandes ou récompenses.

Toutes les opérations financières doivent être journalisées.

Le système doit permettre de répondre précisément à ces questions :

- Pourquoi cette récompense a-t-elle été accordée ?
- Quelle commande l'a déclenchée ?

- Quel montant a été calculé ?
- Quelle règle était active ?
- La récompense a-t-elle été utilisée ?
- A-t-elle été annulée ?
- Qui a effectué une éventuelle validation manuelle ?

# 20. MONNAIE ET CALCULS FINANCIERS

La monnaie principale de la boutique est le franc CFA BCEAO.

- Code ISO : XOF.
- Affichage : FCFA.
- Exemple : 15 000 FCFA.
- Ne jamais afficher `$` pour les prix de la boutique.

Stocke les montants dans une représentation numérique exacte adaptée à XOF. Pour les prix exprimés en francs entiers, privilégie les entiers en base de données et en calcul métier.

N'utilise pas de calculs flottants non contrôlés pour les montants financiers.

Le serveur doit calculer et vérifier :

- prix ;
- sous-total ;
- réduction ;
- livraison ;
- total ;
- montant payé ;
- montant remboursé ;
- commission ;
- récompense ;
- crédit boutique.

Les réductions en pourcentage doivent suivre une règle d'arrondi explicite et cohérente.

Conserve les informations nécessaires pour expliquer les montants appliqués à une commande même si le prix ou la promotion change ultérieurement.
